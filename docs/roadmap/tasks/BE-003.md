## Scoped steps
1. Map canonical account/destination, source/seen state, event, rule, intent and attempt records; store matching/rule/filter/version snapshots directly in each intent. Preserve domain/application boundaries without adding a Match/RuleMatch table or MatchId FK.
2. Add database-enforced identities, referential constraints and indexes for approved dedup, owner reads and due delivery work. Do not rely solely on in-memory checks.
3. Implement scoped contexts/transactions and one outer async mutation gate, with cancellation, bounded wait and guaranteed release; reads do not recursively enter it.
4. Include the gate in every write path: Identity failed-login counters/lockout/rehash/provisioning, rules, source checkpoints/failures and delivery state. Enforce the overview's bounded admission deadline/waiter count; no network I/O under lock/transaction.
5. Generate and inspect migration SQL; run explicit migrations on disposable SQLite. Document app-stopped application, persistent storage and process ownership guard responsibilities.
6. Document consistent backup/restore and PostgreSQL verification path without adding a PostgreSQL provider or claiming a migration ran.

## Detailed edge-case tests
- Create a fresh database via migrations and reopen it; persisted domain values, UTC times, decimal precision and Identity table relationships round-trip exactly under the approved representation.
- Duplicate source/external key and rule/event/channel intent violate their unique constraints; unrelated sources/channels remain distinct. Two selected channels for the same event/rule are legitimate separate intents carrying consistent matching/rule snapshots, not an event/rule-only uniqueness violation. Invalid foreign keys fail under actual SQLite settings; schema inspection confirms no Match/RuleMatch table is required.
- Inject exceptions before commit and verify all writes roll back; commit survives context disposal/reopen. Do not use EF InMemory to substantiate these claims.
- Concurrent mutation callers serialize; cancelled/timed-out acquisition does not steal/release another caller's gate; exception releases the gate for the next operation; no nested acquisition deadlock is introduced.
- Intent-contained snapshots and event/rule references survive allowed soft deletion and rule changes; cascade behavior does not erase delivery/audit history. Unsupported decimal/time values are rejected rather than silently rounded. Rule Version is an application-managed concurrency token per ADR-003 and the forthcoming schema, not SQLite rowversion.
- Review generated SQL for destructive changes; missing/incompatible schema fails startup/readiness clearly rather than automatically performing destructive work. Reapplying already applied migrations is safe in a disposable database.
- Verify the proposed process ownership mechanism refuses a second writer against the same file, including canonicalized path handling; stale ownership recovery follows the approved design, not guessed database deletion.

## Completion criteria
