## Approval gates
- Confirm demo tooling, sandbox receiver versions, CI actions/permissions and any added dependency are explicitly accepted.
- Final acceptance requires documented provider rights/selection/access and actual approved live source evidence. No waiver follows from a successful synthetic demo or green offline CI.
- Secret injection, CI secret changes, publishing artifacts, commits/pushes and deployment need their own authorization. Suggested milestone commits are not historical facts.

## Scoped steps
1. Reproduce restore/build/migration/provision/start/check steps from a clean checkout with approved tools and synthetic identities in isolated local storage.
2. Provide an offline demo covering real login, owned rules, manual categories, simulated earthquake, synthetic source fixtures, both sandbox channels and admin inspection; label each path accurately.
3. Provide a distinct gated live-source procedure with permission checks, baseline behavior, provider units/provenance and actual BE-008/BE-011 evidence links. Do not disable dedup/baseline to make a demo appear busier.
4. Automate offline build/test and relevant restart/integration checks in CI with no live-provider secrets or network dependency by default; fail on actual test failures and expose useful sanitized artifacts.
5. Document app-stopped migrations, database/key persistence, backup/restore verification, one-writer restriction, troubleshooting and canonical PostgreSQL future path; preserve known reliability limitations.
6. Reconcile all AC evidence, approvals, exact application-level prompts, summarized agent outcomes, rejected recommendations and review corrections. Export available conversation only with appropriate redactions; explicitly identify missing history rather than fabricate it.
7. Inspect repository/artifacts for credentials, PII and generated data; verify links/commands and honest statuses. Record only actual authorized commit hashes; propose remaining milestones without creating them implicitly.
8. Produce a concise submission/handoff with implemented scope, executed checks, limitations, unresolved gates and separately approved FUT backlog.

## Detailed edge-case tests
- A clean checkout with only documented prerequisites can restore/build and execute the offline demo/CI checks; undocumented local tools/state/cached secrets are not necessary. Missing required configuration fails with useful redacted guidance.
- Re-running non-destructive setup/provisioning preserves existing account/password/state; isolated reset instructions are clearly scoped and never delete arbitrary database/key paths.
- Restart retains accepted events/intents and valid token keys; published commands do not auto-run destructive migrations or enable a second writer. Backup/restore instructions match BE-011 evidence rather than an unexecuted claim.
- Offline CI runs with internet/provider access unavailable after dependency restore and no real credentials; fixture-only success is labelled accordingly. Live checks require explicit provider approval and cannot run accidentally on every push.
- Demo email/Slack outputs show selected channels and accurate manual/simulated/synthetic provenance; no user can inject source/destination URL. A deliberate source/sender failure is inspectable without exposing credentials.
- Verify AC matrix links point to actual observed results, every live claim names its provider and permitted use, and blocked/not-run outcomes remain visible. No screenshots, counts or commit hashes are invented.
- Inspect prompt/history/log/artifact exports for tokens, passwords, key files, personal recipients and secret URLs; maintain explicit redactions and provenance gaps. Export only available application-level conversation, not hidden platform instructions.
- CI failure exit status/artifact handling and README commands agree; future PostgreSQL and real-channel work remains clearly unimplemented and separately approved.

## Completion criteria
BE-011 is complete; clean-checkout demo and offline CI/check procedure have observed passing evidence; approved live-source evidence and permissions remain separately identifiable; all AC IDs, approvals, reviews and provenance gaps are reconciled. Handoff includes limitations and reproducible commands without secrets or fabricated history. Final user acceptance is requested explicitly, never inferred from documentation or green CI.

## Excluded work
Production deployment, automatic publishing, creating missing historical prompts/commits, mandatory real channel integration, PostgreSQL implementation, frontend/tenants and expanding scope to clear a demo inconvenience.
