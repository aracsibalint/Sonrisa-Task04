## Approval gates
- Accepted baseline includes opaque bearer lifetime, no supported refresh/logout API, lockout/rate limits, role behavior and session-invalidation limitations; do not reopen unchanged decisions.
- API/security/ADR-004 are now aligned: 15-minute opaque access token, expiresIn900. Verify actual framework behavior during implementation; old differing values are historical.
- Approve provisioning input, stable Data Protection application identity, persistent key location and environment-specific protection. Never create/change real credentials merely because a task describes them.
- Confirm accounts/destinations are centrally provisioned and no public registration/reset/user-management/source/destination API is introduced.

## Scoped steps
1. Configure built-in Identity storage/password hashing and approved User/Admin roles using the shared context and write gate for all Identity mutations.
2. Implement idempotent explicit pre-start provisioning from authorized secret inputs; do not reset existing passwords or overwrite destination identity silently.
3. Map only the approved login contract and built-in opaque bearer scheme; do not broadly expose `MapIdentityApi` routes or build custom tokens.
4. Implement role/identity access policies, the canonical current-account read and application-level owner identity plumbing; do not make Admin an ownership bypass. Channel availability is exposed by BE-005.
5. Persist/protect Data Protection keys as specified; fail clearly on missing unsafe configuration rather than silently issuing restart-invalid tokens.
6. Add generic failure handling, approved lockout/rate limits and secret-safe logging; exercise actual login in integration tests.

## Detailed edge-case tests
- Seed synthetic user A, user B and admin; authenticate each through the real endpoint; wrong password, unknown user and malformed input fail generically without leaking account existence or credentials.
- Repeat declarative provisioning without duplicating accounts or resetting a changed password. Require a nonempty unambiguous set with an Admin before mutation; reconcile exact roles, disable absent accounts, and re-enable a later re-added stable identity without deleting history/password rows. Missing required secrets, empty input, conflicts and transaction faults fail explicitly with no partial reconciliation.
- Anonymous protected request fails; valid user cannot satisfy Admin policy; Admin does not acquire another user's owner identity. Machine-ingress credentials are a separate scheme, completed in BE-007.
- Lockout and rate-limit boundaries follow the approved policy; concurrent failed logins/provisioning use the mutation gate without a shared DbContext or deadlock.
- SQLite BUSY/LOCKED/READONLY/IOERR/FULL/CANTOPEN primary faults in login bookkeeping return fixed safe503 without a token and latch storage; ERROR/NOMEM/CORRUPT/CONSTRAINT/MISUSE/NOTADB are not masked as transient storage errors.
- Tampered/expired token fails; a valid token survives application restart with the same key ring/application name; replacing or losing keys invalidates tokens as documented, using isolated test material only.
- Confirm registration, reset, refresh, user-management and unapproved logout routes are absent. If framework serialization includes an unusable refresh value, document the exact contract without advertising refresh support.
- Capture errors/logs and verify no password, bearer value, key material or full destination secret appears; persistence files are excluded from git.
