## Approval gates
- User approves source-bound machine credential handling, transport/rate/body limits, constant-time comparison and configured source identity.
- The recovery architecture selects HMAC-SHA256 over timestamp plus raw body; use the approved API/security framing, key-ID and freshness details. A plain shared-token variant is not the proposed contract.
- Confirm producer external ID, timestamp/magnitude/scale bounds, required simulated label, duplicate/conflict and response contracts.
- Using a temporary isolated test credential is distinct from changing a real deployment secret; real secret operations require authorization.

## Scoped steps
1. Verify the approved raw-body signature protocol and bind its key identity to the server-configured simulated source; never trust a caller-supplied source/owner to select privileges. The sample sender must sign the exact transmitted bytes using the same canonical protocol.
2. Apply approved pre-auth/authenticated rate limits and body/schema validation; authenticate before accepting any event.
3. Convert valid payloads into the canonical normalized earthquake type and invoke BE-006 without a second matching/persistence path.
4. Preserve stable external IDs for retries and canonical equivalent-duplicate/content-conflict behavior.
5. Provide a controlled sample request/sender using injected credentials and an explicit simulated label; keep the demo independent of a real seismic provider.
6. Record transport/auth/validation outcomes safely, with no credential echo in request logging or errors.

## Detailed edge-case tests
- Valid machine credential and valid sample create one event/expected durable intents; missing, malformed, wrong and other-source credentials create no event or intent. Real user/admin bearer credentials cannot substitute for the machine secret.
- Signature vectors cover exact raw bytes, mutated whitespace/body, duplicated/malformed headers, encoding/BOM/compression rejection, skew boundary and expired signature. A newly signed retry with the same event ID deduplicates even after original payload freshness; a changed body with reused identity conflicts. Key rotation mapping to the same source does not reset dedup; revoked/unknown keys fail generically.
- Machine credential cannot call user/admin rule or manual/inspection APIs. Caller source ID/owner spoofing cannot escape its configured source.
- Reject malformed JSON, missing external ID, oversized body, unsupported fields per API contract, wrong magnitude scale, out-of-bound precision/range, invalid/non-UTC timestamp and excessive future occurrence. Every rejection leaves no partial rows.
- Missing/false simulation marker follows the canonical rejection contract; response/evidence never labels the sample as a live earthquake integration.
- Repeat equivalent payload with the same external key, including concurrent requests and restart, yields one event/intent set; changed magnitude/time under that key conflicts without replacing accepted data.
- Rate-limited requests and cancelled calls produce no accidental acceptance; committed-but-response-lost retries reuse the original event. Authentication logs/error bodies disclose no secret or raw authorization header.

## Completion criteria
Real machine authentication and shared acceptance are verified against actual SQLite with auth/invalid/replay cases; the sample sender is reproducible and clearly simulated. Independent security review and shared completion record are complete. Actual sandbox receipt is verified in BE-009/BE-011.
