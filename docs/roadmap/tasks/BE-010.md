# BE-010 — Admin inspection/health/logging

Status: **Not started (approval/dependency gated)**

## Objective
Make accepted events, source health/failures and delivery outcomes inspectable by Admin, with bounded redacted reads and health/logging that accurately distinguish host failure from upstream degradation.

## Explicit dependencies
- [BE-004](BE-004.md), [BE-006](BE-006.md), [BE-008](BE-008.md) and [BE-009](BE-009.md) complete.
- If BE-008 live acceptance is blocked, fixture-based inspection checks may be prepared but this task's dependency/completion remains unmet.

## Files/components expected — proposed
- `src/Alerts.Application/Inspection/` and `src/Alerts.Api/Admin/`: approved event/source/delivery read models/endpoints.
- `src/Alerts.Api/Health/` and built-in structured logging/Meter/Activity wiring.
- Narrow bounded persistence queries; `tests/Alerts.IntegrationTests/Operations/` with actor matrix and redaction/health/failure fixtures.
- Operational inspection examples and symptom-to-state guidance in documentation.

## Approval gates
- Approve canonical endpoint/query/paging/error contracts and exact redaction/PII exposure policy for Admin.
- Confirm readiness/liveness criteria, source staleness/degradation and fatal loop-failure semantics. Do not invent an SLA or silently add an external telemetry exporter/library.
- Align admin delivery DTO/filter states with the recovery flows' Delivered/RetryScheduled and OutcomeUnknown history; the inspected API/security still use Sent and the older retry/attempt vocabulary. Include retained-intent admission pressure alongside outstanding backlog.

## Scoped steps
1. Implement Admin-only bounded event, source status/failure and delivery/attempt inspection using canonical read models; no mutation/replay capability.
2. Expose provenance, evaluation state, source checkpoints/freshness, backlog/next retry and ambiguous/terminal delivery outcomes without secret-bearing details.
3. Add correlation identifiers and sanitized outcome classes across existing flows using built-in observability facilities.
4. Implement liveness/readiness from actual host/database/provisioning/loop state as specified; external provider outage is a visible degradation rather than an automatic restart trigger.
5. Surface queue age/admission failures, gate wait/timeouts and storage-related errors honestly; avoid publishing raw exception/connection strings.
6. Verify inspection consistency against durable state after errors/restart and document operational examples with evidence-class labels.

## Detailed edge-case tests
- Admin can list/detail canonical operational resources; anonymous and regular users cannot. Admin still cannot edit another user's rule through existing rule endpoints; machine credentials confer no inspection privilege.
- Empty state, missing resource, invalid/oversized page input and multiple pages follow canonical deterministic bounded contracts; reads do not require the mutation gate or expose cross-owner rule mutation.
- Source timeout/schema failure/blocked permission and stale observations are distinguished from successful fetches; startup/no baseline and disabled provider state are not labelled healthy live integration.
- Delivery Pending/RetryScheduled/InFlight/Delivered/Failed states and OutcomeUnknown attempt histories agree with persisted records across restart; one channel success cannot conceal another's failure. OutcomeUnknown is an attempt outcome, not an invented extra intent state.
- External outage keeps host readiness per the canonical contract while showing degraded integration state; missing schema, incomplete provisioning, database unavailability or fatal hosted-worker failure affects readiness/host health as specified. No health route leaks secrets.
- Structured log/evidence capture for invalid login, webhook auth failure, provider exception, SQL error and sender rejection contains useful IDs/classes but no bearer/secret/password/full destination URL or complete message body.
- Queue admission rejection and gate timeout produce observable counters/state; slow sender and source failures are distinguishable without claiming measured throughput or production availability.

## Completion criteria
Admin inspection is authorized, bounded and sanitized; host/source/delivery health semantics and observability agree with real durable state. Prerequisites including BE-008 live acceptance are satisfied, review/security checks pass and the shared completion record is complete.

## Excluded work
Admin mutation of others' rules, source/destination CRUD UI/API, manual replay, dashboards/managed monitoring, telemetry exporter deployment and production alerting commitments.
