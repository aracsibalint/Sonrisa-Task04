## Scoped steps
1. Define the domain types required by the canonical data model; BE-003 will map these, not introduce competing entities.
2. Implement one supported category/filter per rule, unique selected channels and category-specific validation using canonical limits.
3. Implement normalized keyword matching, checked-decimal market comparison before display rounding and inclusive earthquake magnitude comparison.
4. Separate malformed input from valid nonmatching input; expose stable application-consumable validation results without HTTP/EF dependencies.
5. Define immutable accepted payload/snapshot behavior and predicate versions required by later atomic acceptance; do not orchestrate transactions here.
6. Build a hand-authored synthetic fixture suite with explicit expected outcomes, independent of external feeds and local culture.

## Detailed edge-case tests
- News: empty/whitespace keyword rejected; minimum/maximum lengths and overflow; NFC composed/decomposed text; approved whitespace normalization on both sides; ordinal case-insensitive matching under different cultures; keyword in title or summary; separator avoids accidentally joining title/summary into a word; regex-like text remains literal; valid nonmatch is not an error.
- Market: synthetic open 100/last 105 and 95 at threshold 5 match; 104.999 does not; equality uses unrounded values; unchanged positive prices do not match a positive threshold. Reject zero/negative prices, excessive scale/precision, overflow, unsupported symbol/window, zero/negative threshold and invalid boundaries from canonical contracts.
- Earthquake: magnitude equal to minimum matches; just below does not; valid negative magnitudes follow approved bounds; wrong scale, out-of-range values, excess decimals and materially future occurrence fail validation; past occurrence alone does not trigger historical replay logic.
- Rule shape: reject unsupported category, missing/wrong/multiple filter variants, empty/duplicate/unknown channels and invalid identifiers. Destination availability/ownership is verified later in Application, not guessed in a pure predicate.
- Equivalent normalized payloads yield identical results regardless of field input ordering/culture; failure produces no partial match result. Time-dependent validation uses a controlled clock, not flaky wall-clock assertions.

## Completion criteria
