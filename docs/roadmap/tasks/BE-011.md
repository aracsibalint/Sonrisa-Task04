## Detailed edge-case tests
- Full actor matrix: anonymous, user A, user B, Admin and machine credential against login, own/other rule operations, manual event, webhook and inspection. Actual Identity login is exercised, not only a fake handler.
- Each category has exact boundary match/nonmatch and invalid payload; email-only/Slack-only/both receipts match selected channels. No-match and unauthorized input yield no notification; paused rules produce no new matches.
- Rule create/edit/pause/resume/delete versus event acceptance is deterministically ordered around commits; no historical replay; snapshots remain unchanged after subsequent rule/destination changes.
- Duplicate and conflicting keys, concurrent acceptance, crash before commit and crash after commit/lost response preserve one logical event/intent set. Rollback at every persistence stage leaves no orphan/partial channels or prematurely seen identities. Verify matching/rule snapshots live on intents and no separate Match/RuleMatch table is introduced.
- RSS initialization/304/validator failures and mid-response crash replay preserve baseline/seen invariants; market slot expiry, identical later values, stale response and restart gaps obey approved semantics.
- Sender acceptance followed by host interruption before completion yields a documented possible duplicate; attempt bounds, expired-claim recovery and terminal non-resend remain correct. One failing channel/source does not silently stop the other loops.
- Outstanding/retained-intent, active-rule, payload and gate admission/waiter bounds reject visibly without partial work; slow external I/O does not hold the write gate. Retention saturation pauses ingestion for review without purging history or blocking existing delivery/rule administration. A second app writer is refused rather than pretending the in-process gate is distributed; Identity lockout/provisioning races participate in the same all-writer ordering.
- Restart retains SQLite state and valid key-ring tokens; real isolated backup/restore rehearsal preserves consistency and recorded limitations. PostgreSQL remains a documented verification path, never an asserted executed migration.
- Malformed/oversized/compressed hostile input, XML entities, redirect/URL injection, precision/time extremes, rate-limit/lockout and logs/errors uphold canonical security contracts.
- Approved live endpoints actually normalize intended RSS/market data with source labels/units; baseline suppression remains active. Record permission/region/attribution checks and any capture gaps; sandbox receipts do not establish production channel integration.
