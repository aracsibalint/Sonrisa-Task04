## Review cycle 1 — exact numeric correction

FACT: Parent's independent review found a blocking precision defect: checked decimal cross-products silently rounded within approved input ranges. Reproducer open `999999999999.99999999`, last `100`, threshold `99.99999999` incorrectly matched; mathematically RHS exceeds LHS by `0.0000000000000001`. The review was correct; `checked` detects overflow, not loss of fractional precision.

Fix: extract decimal's 96-bit coefficient/scale with `decimal.GetBits`, lift to eight fractional places using BCL BigInteger **before subtraction or multiplication**, then compare `100*abs(L-O)*100000000 >= T*O`. Both sides share denominator10^16, so comparison is exact. No division, floating point, new dependency, range reduction or wire/storage representation change. Predicate version1 and intended unrounded semantics are preserved. `SignedMovementPercent` explicitly documents that its decimal result is display-only and may round.
