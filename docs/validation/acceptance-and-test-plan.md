## Strategy and test layers
- **U — unit:** pure normalization, matching, validation, identity and scheduling policy; fixed UTC clock, deterministic slots and exact decimal values.
- **R — relational integration:** actual EF Core SQLite provider, foreign keys enabled and real migrations; isolate each database. **Do not use EF InMemory.**
- File-backed SQLite is mandatory for restart, locking, concurrent writers and durability tests; SQLite in-memory may supplement isolated relational checks but proves no restart persistence.
- **A — API integration:** `WebApplicationFactory`, real application registrations, migrated SQLite and provisioned synthetic identities; controlled source transports and receivers.
- **E — local end-to-end:** real host/database, local mail capture and fake Slack HTTP receiver; exercise ingestion through durable outcomes and receiver captures.
- **L — permission-gated live:** separately invoked checks against approved real RSS/market endpoints, never a default CI prerequisite. **D — document/evidence review.**
- Default CI uses synthetic data and denies unintended external network access. Faults and clocks are deterministic; synchronize concurrency tests with barriers, not sleeps.

## Authentication, ownership and input security
- AUTH-01: exercise the **actual login endpoint** and built-in Identity opaque bearer issuance/validation; do not assume JWTs. Test wrong password, unknown user, missing/malformed/tampered tokens, expiry around the proposed 15-minute lifetime and valid token reuse across requests. Test configured lockout/rate limits; credentials are provisioned outside the repository, never default passwords.
- Test explicit login-only routing: no blanket `MapIdentityApi`, registration/recovery/management or refresh endpoint. The framework response's refresh field is present but **unused/discard-only**; it must not work as an access token or enable refresh. Re-login obtains new access after expiry. Role/account changes do not instantly invalidate issued claims; no logout-revocation promise.
- A fake authentication handler may supplement focused tests but cannot satisfy AC-001/011. Unauthorized resource requests create no domain writes; failed login may legitimately write Identity lockout state **under the same gate**. Errors/logs disclose no passwords, tokens or internal exceptions.
- AUTH-02/OWN-01: enumerate every eventual route and verb with anonymous, owner A, other user B and admin. Include list filtering, guessed identifiers, body owner/role spoofing, all lifecycle operations and deleted resources.
- Admin may inspect operational data but cannot edit others' rules; test its own rules as an owner where the approved role contract permits. Assert approved 401/403/non-disclosing-not-found behavior, not invented route/status contracts.
- RULE-01: null/empty/whitespace bodies/keywords, unknown categories/channels, missing or multiple filters, incompatible category fields, zero channels, duplicate channels, unavailable destinations, invalid numbers and length boundaries.
- Configured/provisioned destinations proposal: request bodies cannot redirect email/Slack or inject fetch URLs; test unknown destination references and cross-owner destination selection. No arbitrary URL fetching or recipient override.
- WEB-01: proposed **HMAC-SHA256 over timestamp plus exact raw body bytes**, with freshness validation and a separate controlled-producer secret. User/admin bearer tokens alone cannot authenticate this webhook. Missing/invalid signatures create no event/intent/send.
- Cover known signature vectors, wrong key, altered timestamp/body (including whitespace/encoding), malformed signature, stale/future timestamp and repeated valid request. Verify fixed-time signature comparison and bounded raw-body handling; final vectors require the wire contract's exact framing/encoding/headers and freshness allowance, not invented values.
- Test wrong media type, truncated/invalid JSON, null/missing fields, invalid IDs/timestamps/magnitude/scale, unknown fields per wire policy, body/depth/string limits and request cancellation. Webhook/manual body bound is proposed 64 KiB; use minus-one/exact/plus-one bytes. Other wire-level limits are not established by the reviewed architecture/ADRs; reconcile them before executable assertions without claiming excluded API documents lack definitions.
- Replay producer IDs concurrently and after restart: same key/normalized fingerprint returns original event; changed content returns 409, never overwrite. Admin manual idempotency is actor-scoped with the same replay/conflict behavior. Inspect redaction, bounded errors, and credential-safe logs.

## Deterministic matching and lifecycle
- MATCH-01 proposed news contract: normalize keyword/phrase and plain-text title plus summary (joined by a space) with Unicode NFC and whitespace collapse, then ordinal case-insensitive **substring** comparison. Cover composed/decomposed Unicode, casing/culture, word-internal and cross-title/summary matches, empty normalized text, HTML/entities and excluded `content:encoded`; no regex, stemming, linked-page/resource fetch or whole-word requirement. Escape rendered HTML/Slack mentions.
- MATCH-02 proposed inclusive magnitude: open `100`, threshold `5`, last `105` and `95` match; `104.999` and `95.001` do not; `105.001` and `94.999` match. Zero movement does not match a positive threshold.
- Compare `100 * abs(last - open) >= threshold * open` before display rounding; test representable precision boundaries, checked overflow, invalid/locale-formatted strings, null, zero/negative prices and nonpositive thresholds. Never use previous-poll price as denominator.
- MATCH-03 proposed earthquake contract: scale **Mw**, valid event magnitude **-2 through 10 inclusive**, matching `magnitude >= minimum`. Test -2/10 accepted, -2.001/10.001 rejected if representable, unsupported scales rejected, and minimum 5 with 4.999/5/5.001 yielding nonmatch/match/match. Final precision and rule-input range validation follow the wire contract; magnitude is not percent.
- LIFE-01: persisted history predates rule create/update/resume; assert zero historical matches. New qualifying events match only active rules; paused-rule ingestion still advances dedup state. Soft delete hides rules while preserving history/foreign keys; pending intents survive pause/update/delete with immutable payload, rule-version and destination-version snapshots.
- Race rule changes against ingestion with barriers: commit order selects one coherent rule version, never mixed old/new filters/channels. Manual old occurrences are intentional newly ingested events, not backfill; manual news bypasses RSS baseline transport state but not normalized category validation.

## Synthetic source fixtures and failure handling
- RSS-01: hand-authored XML, not copied copyrighted feeds; initial A/B creates durable suppressed identities only; later A/B/C emits C once; restart with unchanged feed emits nothing. An empty valid initial feed establishes an empty baseline.
- Cover empty GUID/link fallback, absent identity, same GUID edited, duplicate GUID, same link/different opaque GUIDs, escaped query strings, UTF-8/entities, CDATA/HTML, missing/invalid dates and source scoping.
- Test publication time just below/at/above baseline cutoff: only strictly later is eligible; future times at receipt +5 minutes are allowed, beyond rejected. Failed initialization/whole-document size/item/parse failure leaves checkpoints unchanged; initial 304 without baseline requires unconditional fetch. Rejected malformed dates are not permanently seen, so corrected items can be accepted.
- Later RSS polls commit **per item**, retaining already committed items on later backpressure/DB failure; response validators advance only after all valid items are accepted or deterministically suppressed. Re-fetch must dedup prior successes and finish remaining work without skipping it.
- MKT-01: conditional Binance BTCUSDT uses one response's open/last and exact 24-hour epoch-millisecond window, **USDT not USD**. Test close time at/beyond receipt -5 minutes and +1 minute, invalid symbol/interval/decimals, and exact UTC-minute slot boundaries captured before request. BBC/Coinbase remain alternatives, not automatic fallback or mandatory adapter implementations; never invent Coinbase window timestamps/freshness if separately selected.
- Same slot retries/concurrent inserts yield one accepted immutable snapshot; changed retry data cannot overwrite it. Identical prices next slot intentionally produce another observation/match under the proposal: **not crossing detection**. Restart skips missed slots, not backfill.
- FAIL-01: synthetic 304, 401/403/404, 418, 429 with missing/valid/malformed Retry-After, 5xx, timeout, cancellation, disconnect, HTML-200, wrong content type, malformed XML/JSON and compressed oversize responses.
- Prohibit XML DTD/external entities; block unexpected redirects/hosts and fetching article links. Assert byte/decompressed limits, safe parse failure, bounded diagnostics, backoff and preserved validators/state without fabricated events or zero prices.
- Inspect last attempt/success/valid observation, freshness versus reachability, next attempt and blocked/degraded status. Proposed backoff starts at cadence, doubles to one hour and honors longer valid Retry-After; 401/403/404/ban/region restriction blocks for operator action. Test market stale after five minutes without a valid observation and RSS fetch stale after three intervals, not merely old news. Outages do not stop accepted dispatch or justify fabricated history.

## Atomicity, concurrency, restart and duplicate semantics
- TX-01: inject faults during candidate evaluation, after event insertion, between channel intents, immediately before commit and immediately after successful commit. No separate persisted match entity is assumed. Reopen SQLite using a fresh context/process and inspect durable state, not tracked entities.
- Before-commit failure leaves no partial event/intent/checkpoint set; after-commit recovery retains the complete accepted set. Retry resolves source identity and `(event, rule, channel)` unique keys; capacity rejection returns no false acceptance and never truncates matching rules arbitrarily.
- Fault atomic initial RSS baseline, per-item event/seen commits, separate whole-poll validator checkpoint, and market-slot acceptance. Full-disk/write-error, lock contention and cancellation must release the asynchronous write gate without leaking a transaction or deadlocking later work.
- Concurrent manual/webhook/poll ingestion, rule mutation, source checkpoints, dispatch claims/results **and Identity lockout/provisioning mutations** exercise the same gate; include failed logins racing event acceptance. Assert no bypass or nested-gate deadlock; network/normalization work stays outside the gate/transaction. A second app instance against the same local DB is refused; no network-filesystem deployment is supported.
- DUP-01: assert `Pending -> InFlight -> Delivered | RetryScheduled | Failed`; claiming persists an incremented attempt and attempt record before sending outside the gate. Restart after claim marks abandoned attempt `OutcomeUnknown`, retrying only if fewer than **five total attempts** were consumed; otherwise terminal `Failed` records uncertainty, even if the process died before actually sending.
- Lost acknowledgement/timeout after receiver acceptance is **ambiguous**: retry can create a second external message. Assert one logical intent plus truthful attempts/outcomes, demonstrate possible duplicate receiver captures, and never claim exactly-once delivery.
- Evidence separates duplicate ingestion, duplicate logical intents and duplicate external sends. Verify attempts 1–5, no sixth claim/send, permanent rejection without further retries, and transient retries from 30 seconds with exponential/jitter cap 30 minutes while honoring a longer valid Retry-After. These policies are now defined proposals awaiting approval, not missing design definitions.

## Sandbox delivery and independently failing channels
- SEND-01/MAN-01: each category traverses ingestion, matching and delivery to local mail capture and fake Slack; compare equivalent normalized manual/simulated/fixture events without claiming those inputs are live.
- For email-only, Slack-only, both and nonmatching rules, assert exact intended logical intents and receiver captures, recipient/destination, source labels, currency/window, encoding and sanitized content; no send to unselected channels.
- Fail email while Slack succeeds, then reverse; successful channel is not resent merely because the other failed. Exercise permanent/transient HTTP/SMTP rejection, 429, timeouts, malformed responses and receiver acceptance with lost acknowledgement.
- Restart with each named delivery state and verify retry budget, terminal state and admin-visible attempt history. `Delivered` means receiver/transport acceptance, **not human reading**. Missing destination version fails visibly instead of redirecting an old intent; secret rotation may resolve the same stable target version. Persist no secret-bearing webhook URLs; redact sensitive payloads/secrets.

## Persistence, migration and portability verification
- DB-01: inspect generated SQLite migration SQL for keys, foreign keys, uniqueness, indexes, nullability, rebuilds and destructive/narrowing changes **before applying it to a disposable database**. Verify canonical invariant decimal text round-trips exactly, UTC epoch milliseconds and application-managed concurrency versions; numeric matching is bounded application decimal work, not lexicographic SQL text sorting.
- Plan clean-database migration and supported upgrades with seeded users/rules/events/source state/intents; failure must not report healthy. Stop writers for migration; no automatic shared-environment startup migration. Test consistent backup/restore including SQLite WAL and separately protected Data Protection keys; rollback binaries only across compatible schemas. No silent history pruning; destructive recovery requires separate approval.
- Restart the host against the same file and verify identities/login, rules, baseline/seen keys, market slots, outcomes and recovery. Verify key persistence/protection separately from DB, unexpired opaque tokens across supported restart and re-login after expiry; do not mistake a DB-only backup for complete authentication portability.
- Document PostgreSQL verification separately: provider-specific migrations/SQL review, decimal/time/collation/unique-null semantics, concurrency and transaction behavior, then rerun relational/API suites on real PostgreSQL before any portability claim. It is not implemented or executed here.

## Live gates, operating limits and evidence
- RIGHTS-01/LIVE-01 require recorded operator approval of exact providers/endpoints, coverage, symbol/currency/window, intended recipients/use, jurisdiction, redistribution/attribution restrictions and unresolved terms. HTTP 200/public access is not permission.
- Live checks are explicit opt-in outside default CI; use approved bounded requests and record normalization and limitations separately from fixtures. RSS first fetch may only establish baseline; a smoke probe does not prove new-item matching or delivery. Blocked live acceptance remains visibly blocked.
- Test proposed safety limits at below/exact/above boundaries: **100 active rules total, 20 per owner, two channels/rule and 200 intents/event**. Concurrent create/activate enforces caps under the gate; all matching rules are included or the transaction rejects atomically.
- Payload bounds: **100 RSS items, 2 MiB decompressed RSS, 16 KiB normalized news text; 64 KiB market/webhook/manual bodies; pagination maximum 100 rows**. Test compression expansion and full-document failure without checkpoint advancement; wire contract must settle text-size counting where bytes/characters differ.
- Gate bounds: **32 waiters, two-second admission deadline**; test saturation, timeout and cancellation release with deterministic synchronization. Capacity: projected outstanding intents **<=20,000**, retained **<=250,000**; exact limits accepted, overflow defers/rejects whole event atomically, ingestion pauses for retention/operator review, existing delivery/rule administration remain available and history is not silently purged.
- Scheduling/transport bounds: NASA hourly, market every 60 seconds, one in-flight poll/source, one dispatcher/channel and **10-second attempt timeout including delivery**. Test readiness for persistence/configuration independently from liveness and upstream outages; inspect gate wait, depth/oldest age, failure, match-duration and disk-growth signals without logging secrets.
- All limits above remain **unmeasured proposed safety defaults**, not approved production commitments. Measure local durations/resource use with environment/workload; never infer capacity, latency, availability or completeness guarantees. Approval is still required; unspecified wire details must be reconciled, not filled with invented constants.
- EVID-01 record: evidence ID; AC/scenario IDs; approved contract/version; commit/build/runtime/OS; test layer; fixture/source class; clock/config/DB setup; exact command; expected/actual counts and states; pass/fail/blocked/skipped; redacted logs/TRX/receiver captures; limitations; defect owner. Never put credentials in evidence.
- **Planned, not executed:** `dotnet --info`; `dotnet build <solution> -c Release`; `dotnet test <test-project> -c Release --logger "trx;LogFileName=acceptance.trx"`; `dotnet ef migrations script --project <persistence-project> --startup-project <api-project> --output <review-output.sql>`.
